# Versionierung der Lernpakete

Teil des Skills Baue-Lernpaket (Ablauf in `SKILL.md`). Nur lesen, wenn es gebraucht wird.

Jedes E-Learning trägt seine Version selbst. `build-scorm.py` ruft dafür bei jedem Bau `scripts/version.py` auf (für eine Seite ohne Paket, z. B. ein Arbeitsblatt, geht `python .claude/skills/Baue-Lernpaket/scripts/version.py --file <datei> --aenderung "..."` auch direkt).
- **Anzeige:** `<span class="ver" data-datum="28.10.2026">V1.3</span>` im Benennungsfeld: auf dem Bildschirm nur `V1.3`, ganz klein oben rechts. Im Druck und im PDF-Export mit Datum (`V1.3 · 28.10.2026`), damit man bei jeder Abgabe sieht, mit welcher Version gearbeitet wurde. Alte Seiten ohne `span.ver` bekommen ihn beim Bau eingesetzt.
- **Änderungsliste:** HTML-Kommentar `VERSIONEN` direkt nach `<title>`, unsichtbar im Dokument, neueste Zeile oben, eine Zeile je Version: `V1.3 | 28.10.2026 | Commit folgt | Tippfehler in Aufgabe 2 korrigiert`. Nur das Skript schreibt hinein.
- **Commit:** Ein Commit kann seine eigene Nummer nicht enthalten. Deshalb steht bei der neuesten Version zuerst `Commit folgt`; der nächste Bau dieses E-Learnings ersetzt das durch den Commit (kurz), mit dem die Zeile eingecheckt wurde. Ältere Versionen haben so immer ihren genauen Commit: Zurückholen mit `git show <commit>:<pfad>` (Pakete liegen nicht in Git: alte Fassung der Quelle holen und neu bauen).
- **Wann eine neue Nummer:** Ist die neueste Version noch nicht committet (`Commit folgt`), bleibt es bei ihr (Datum von heute, `--aenderung` wird angehängt). Sonst entsteht eine neue Version, wenn sich der Quellordner seit dem Commit der letzten Version geändert hat oder `--aenderung` etwas Neues beschreibt (z. B. nach einer Änderung an `scorm-api.js`). Ein bloßes Neubauen ohne Änderung erhöht nichts.
- **Hauptnummer** (V2.0) bei Änderungen an Aufgaben, Punkten oder Struktur: Das Skript erkennt sie selbst (Zahl der Aufgaben, Niveaus und Felder, `data-k`, `data-ok`, `data-keys`, `data-tol`, `data-score`, `data-gewicht`; in der Übungs-App Einträge und Antworten) oder `--major`. Sonst **Nebennummer** (V1.3) für Korrekturen. Eine Hauptversion meldet das Skript als Warnung: Da die ByCS das Paket aus dem Teamordner automatisch nachlädt, können laufende Versuche durcheinanderkommen. Hauptversionen möglichst nicht mitten in einer Bearbeitungsphase committen und das der Lehrkraft vor dem Commit sagen.
- Test: `python .claude/skills/Baue-Lernpaket/tests/version.test.py` (Lebenslauf einer Version in einem Test-Repo).
